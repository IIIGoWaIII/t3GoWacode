Context

This is a fork of T3 Code. The fork keeps exactly one patch on top of upstream: a fix to the OpenCode provider adapter that surfaces OpenCode native Task subagents in the Agents panel, including background tasks that finished while a previous session was idle. The sync script rebases main onto upstream/main and force-pushes to the fork, so this patch is re-applied on every sync and can conflict.

What the fix does

Files touched by the patch: apps/server/src/provider/Layers/OpenCodeAdapter.ts (+403), apps/server/src/provider/Layers/OpenCodeAdapter.test.ts (+1552/-8), pnpm-lock.yaml (+2).

The finished behavior that must keep working:

  1. Foreground tasks. A tool part of type task drives task.started, task.updated, task.completed lifecycle events that render as rows in the Agents panel, without hiding the tool row.
  2. Background tasks. A terminal completion arriving as a synthetic <task>...</task> text envelope, or as <task_result>/<task_error> child parts in a user message, emits task.completed with a clean summary.
  3. Resume / reconnect. When a session is reused, prior task history is hydrated from session.messages, seeding lifecycle state and emitting synthetic terminal notices. Live task events arriving during hydration are buffered and drained afterwards.
  4. Isolation. Forked sessions (a cwd change) do not hydrate cloned background history.
  5. Safety. Completed task_id values are not revived. Forged nested envelopes do not create phantom tasks.

Key functions and state

New state on the session context:

taskLifecycleByPartId: Map<string, OpenCodeTaskLifecycle>
taskLifecycleByTaskId:  Map<string, OpenCodeTaskLifecycle>
taskHydration: { active: boolean; bufferedEvents: OpenCodeSubscribedEvent[] }
reused: boolean   // from resolveSession: true for reuse, false for created/forked
Function Semantics
taskLifecycleFromPart(part) Extracts a lifecycle from a tool part: taskId (from task_id or sessionID/sessionId), model (providerID/modelID), description, subagent_type, background, title.
OPENCODE_TASK_ENVELOPE_PATTERN Regex for <task id="..." state="completed|error">...</task> with child <task_result>/<task_error> tags.
taskNotificationsFromPart(part) Yields terminal notifications found in synthetic shapes (user-message text or parts).
emitTaskNotification(context, notification, turnId, part) Emits task.completed from a terminal notice.
reconcileTaskToolPart(context, part, turnId, event, opts) Central projector for tool parts. Emits task.started/task.updated/task.completed, updates both maps, honors the reactivation guard. backgroundOnly mode is used during hydration so foreground rows are not duplicated.
hydrateReusedTaskHistory(context) Reads session.messages, seeds lifecycle from assistant tool parts with backgroundOnly, emits notifications from user-message shapes. Never replays foreground history.
isTaskLifecycleEvent(event) True for message.part.updated on a task tool part or a part carrying notifications.
handleSubscribedEvent(context, event, {bypassTaskHydration}) While taskHydration.active is set, task-lifecycle events are buffered into bufferedEvents instead of processed. bypassTaskHydration: true disables the buffering for the drain pass.
drainTaskHydration(context) Replays buffered events with the bypass flag, then clears active.
startEventPump(context) Establishes event.subscribe before any history replay so a background completion cannot arrive between snapshot and subscribe. An initial subscription rejection fails session startup. The stream stays scope-owned.

Session start ordering that matters:

  1. event.subscribe (subscription established first)
  2. emit session.started / thread.started
  3. exit gate check
  4. if reused: hydrateReusedTaskHistory then drainTaskHydration
  5. the event stream pumps; task events arriving during step 4 are buffered and drained right after

Forked sessions (reused: false) skip step 4 entirely. This is deliberate isolation, not an omission.

Conflict playbook

apps/server/src/provider/Layers/OpenCodeAdapter.ts

  1. For every conflicted hunk, read both sides: git show upstream/main:apps/server/src/provider/Layers/OpenCodeAdapter.ts and the local HEAD version.
  2. If upstream already tracks Task lifecycle (its #7393 implementation merged): adopt upstream's structure and port the local hardening onto it: hydration with live-event buffering, envelope/notification parsing, the reactivation guard, and subscribe-before-replay ordering.
  3. If upstream does not: take the local hunk unchanged.
  4. Keep both maps plus the taskHydration state on the session context. Keep reused coming out of resolveSession.
  5. Keep the ordering in startEventPump: subscribe first, then stream. Keep handleSubscribedEvent buffering while hydration is active.
  6. If upstream added an equivalent helper under a different name, drop the local one and rewire call sites. Never keep two implementations of the same behavior.
  7. Move comments with the code they describe. If a comment no longer matches after the merge, update it.

apps/server/src/provider/Layers/OpenCodeAdapter.test.ts

  1. Upstream may add its own Task tests. Keep both: upstream tests cover the base feature, local tests cover the hardening. Drop only exact duplicates.
  2. Local tests depend on the SDK fake and session fixtures. If upstream changed the test harness, port the local tests to the new harness rather than fighting it.
  3. Do not delete a local test to make the suite pass. A removed test is a removed guarantee.

pnpm-lock.yaml

  1. Do not hand-edit the lockfile. It only gained two deprecation entries.
  2. After resolving code, run vp i (or pnpm install) from the repo root to regenerate it, then stage it.
